The production alignment_for implementation loads the explicit map, checks the current ordered basename/size identity and frame count, and never invokes a new solve in that branch. The wrapper binds and rechecks retained map bytes, records original content hashes and checks them again after completion. Fresh alignment output is explicitly located in the new output directory, outside the source tree. The wrapper also requires every map index placed. Rebuilding cannot silently update an executable pin: the explicit path/hash or the published manifest must match actual bytes, and executable identity is checked again before completion. Historical rendering scripts remain separate.

The owned Windows child job enforces committed-memory, observed CPU, wall-time and bounded-log limits. Failed exit, helper error, failed child-tree terminal accounting or cleanup failure stops before a completion receipt. Full RGB16 TIFF, nonempty ICC and dimensions matching the actual cropped analysis domain are required. The full-resolution JPEG preserves dimensions and ICC; the separate1617 overview is orientation only. Completion explicitly awaits independent photographic review. This establishes a usable execution contract, not successful runtime equivalence or image quality.

One generic-use qualification was sent to the author: production intentionally lets a retained map's resampler override the catmull-rom CLI argument. The garnet map actually declares catmull-rom, so the imminent comparison is held correctly. For other maps, require that declaration or record/report the actual sidecar resampler rather than implying that the flag won. No broad source changes or extra framework are needed for this review.

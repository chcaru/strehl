# M8 — decoder scratch, measured

Harness for `docs/research/M8-scratch-measured.md`. It answers one question:
**what does the stacker's `per_worker_bytes` model leave out, and how much is it?**

Nothing here writes anywhere except `experiments/m8-scratch/data/`. `C:\dev\macro`
and `D:\macro-dark-frames` are opened read-only, by the decoder, and never written.

`rawler` is measured strictly as a black box (`AGENTS.md`: its source is
link-freely, do-not-read). Every statement about the decoder below comes from
calling `strehl_raw::decode` and watching the process from outside.

## What is here

| File | What it is |
| --- | --- |
| `src/mem.rs` | The instrument. Raw `K32GetProcessMemoryInfo` / `PROCESS_MEMORY_COUNTERS_EX` FFI, plus a polling sampler. Two independent readings: kernel-maintained peaks (no sampling error) and a poller (for phase attribution). |
| `src/main.rs` | Modes `selftest`, `null`, `single`, `seq`, `conc`. CSV on stdout, commentary on stderr. |
| `run-m8.ps1` | The stage driver. One stage per measurement. |
| `m8_analyse.py` | Every fit, with standard errors, model comparison and out-of-sample prediction. |
| `negative-control.ps1` | Regresses the shipped code one constant at a time and checks the test that should catch it actually does. |
| `data/*.csv` | Raw output. Committed, so the fits can be re-run without re-measuring. |
| `data/analysis.txt` | The full analysis output the report quotes from. |
| `data/logs/` | Per-run stdout/stderr, 456 files. **Gitignored** — the measurement lives in the CSVs and the report, not in scratch logs (same convention as `experiments/m5-diffraction/.gitignore`). Regenerated by any `run-m8.ps1` stage. |

## Build

`cargo` is not on `PATH` in a fresh shell:

```powershell
$env:PATH = "$env:USERPROFILE\.cargo\bin;$env:PATH"
cd C:\dev\blog\death-of-software\projects\strehl\experiments\m8-scratch
cargo build --release
```

This crate is its own `[workspace]`. It path-depends on `crates/strehl-raw`, so
it is not part of the main workspace's `cargo test --workspace`.

## Run, in order

Controls first. Nothing downstream of a failed control is worth reading.

```powershell
.\run-m8.ps1 -Stage selftest         # 13 harness controls, S0-S6           (~30 s)
.\run-m8.ps1 -Stage null             # real-data null + known-size control   (~1 min)
.\run-m8.ps1 -Stage crossinstrument  # the external poller vs the child      (~1 min)
```

Then the decoder, in isolation:

```powershell
.\run-m8.ps1 -Stage single           # 660 isolated decodes, 6 corpora, 3 pools (~6 min)
.\run-m8.ps1 -Stage seq              # retention: 138 decodes, one live at a time (~3 min)
.\run-m8.ps1 -Stage conc             # the scratch fit: k = 0..32 concurrent    (~12 min)
```

Then the real stacker, with `RAYON_NUM_THREADS` pinned on every run:

```powershell
.\run-m8.ps1 -Stage floor            # the process floor: N = 1..8 at one thread (~1 min)
.\run-m8.ps1 -Stage stack            # threads swept at fixed N, N swept at fixed threads (~4 min)
.\run-m8.ps1 -Stage reps             # 4 repeats per condition, for the uncertainty (~5 min)
.\run-m8.ps1 -Stage shape            # SYNTHESIS 3.2.1 assertion 1, pinned pool  (~2 min)
.\run-m8.ps1 -Stage holdout          # 119MSDCF. Never fitted. Only predicted.   (~1 min)
```

Then the analysis:

```powershell
python m8_analyse.py            # everything
python m8_analyse.py single     # one section: single | seq | conc | stack | plan
python m8_analyse.py all > data\analysis.txt
```

## The negative control on the shipped tests

M8 added constants and a model to `crates/strehl-cli/src/stack.rs`. A test that
has never been seen to fail is not evidence, so:

```powershell
.\negative-control.ps1
```

It regresses six things in turn — zeroing `DECODER_SCRATCH_BYTES`, inflating
`PROCESS_FLOOR_BYTES` 10x, breaking `reduce_levels` off-by-one, swapping the two
memory models both ways, and softening the `describe()` lower-bound wording —
runs `cargo test --workspace` after each, and requires that the specific test
meant to catch each one goes red. It then restores from a byte copy and requires
the suite to be green again at the same test count.

It restores from a **copy**, never `git checkout --`, which would revert to HEAD
and destroy uncommitted work. `Copy-Item` preserves the source mtime, so every
write is followed by an explicit `LastWriteTime` bump or cargo skips the rebuild
and reports a stale result.

## Verifying the CLI change end to end

```powershell
$env:PATH = "$env:USERPROFILE\.cargo\bin;$env:PATH"
cd C:\dev\blog\death-of-software\projects\strehl
cargo build --release
$env:RAYON_NUM_THREADS = '32'
.\target\release\strehl.exe stack C:\dev\macro\test\coffee-bean -o out.tif                       # default, 18 chunks
.\target\release\strehl.exe stack C:\dev\macro\test\coffee-bean -o out.tif --memory-model m8     # opt-in, 15 chunks
```

Both print a `predicted peak` line. MEASURED: the default plan peaks at 6902 MiB
against a prediction of 7.06 decimal GB (−2.4%); the `m8` plan peaks at 5768 MiB
against 5.87 decimal GB (−2.9%).

## Things that will bite you

- **Pin `RAYON_NUM_THREADS` on every run.** MEASURED: the same binary on the same
  22 frames peaks at 833 MiB at one thread and 4122 MiB at 32. An unpinned
  measurement measures the machine, not the code.
- **Working set and private commit are different instruments**, and self-test S3
  proves it: a 1024 MiB allocation that is never touched moves commit by
  +1026 MiB and working set by +0.0 MiB. Report both or say which.
- **Peak depends on `chunk_len`, not only on `chunks`.** At `chunks = 20`, a stack
  with `chunk_len = 1` peaks 30% below one with `chunk_len >= 2`, because a worker
  that decodes a single frame is only briefly at its own high-water mark.
- `data/stack.rs.negctl-backup` is written by `negative-control.ps1` and is not
  committed.

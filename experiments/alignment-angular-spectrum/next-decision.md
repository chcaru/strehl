**One next product question: remove the redundant integer round trip between full-resolution gather and the existing f32 pyramid inputs.** This is a current source bottleneck, not a new global optical model. `align_cmd.rs::warp_frame_in_place_fullres_outputs` already computes each gathered site in `WarpScratch.dst`. `writeback_fullres_site` then applies inverse WB, adds black, rounds/clamps to u16 and writes `Frame.data`. Immediately afterward `merge_cmd.rs::load_frame` calls `extract_planes`, which reads those integers, subtracts black and clamps into its already allocated four f32 planes. Original storage stays u16; these consumed arrays already exist.

ARGUED implementation: a small full-resolution gather sink fills the current compact destination planes directly while retaining full-grid coordinates, site order, coverage, inverse WB, current nonnegative clipping, CA guards and the same demosaic/resampler arithmetic. Keep the no-warp/plane fallback unchanged. First give that sink the exact old round/clamp/subtract operations: its equality with the existing route is the control for eliminating remosaic/deinterleave traffic. Then the single precision candidate omits only the intermediate round; it retains sensor-range clipping and the existing black clamp. This is distinct from the rejected signed-black treatment and does not reopen it. Both real gathering and `gatefloor::Probe::run` must consume the same sink policy; leaving the probe quantized would silently measure another transfer. The shared confidence pass must follow the same `load_frame` path.

The unrounded precision change is a hypothesis, not a demonstrated photographic fix. Before nonlinear fusion, ordinary unsaturated rounding differs by at most 0.5 input DN per sample; that does not justify promising recovery of the much larger measured boundary errors, and the nonlinear gate can amplify a small perturbation. Removing the write/read traffic might supply useful speed even if the precision candidate loses. The source observation alone supplies no timing percentage.

# Final fixed38 quality reader interface

Prospective source preparation only. The numerical definitions and bars remain
in next-quality-reader-preregister.md. Root review and a committed exact command
precede every computation. This adds no product invocation or quality threshold.

CLI independent-quality-score.py requires --matrix, --target,
--target-verification, --instrument-commission, --release, each with its
corresponding --NAME-sha256, and a fresh --output directory. Release uses
m194g-quality-execution-release-v1, scope score. Its exact source closure is
the new controller plus independent-quality-io.py, independent-quality-metrics.py,
independent-quality-adapter.py, independent-quality-readout.py,
independent-rgb-tiff.py, independent-production-bridge-read.py and
independent-private-bridge-read.py. No target/optical/noise generator is imported.
All four data-entry files and fixture/preregister/target/instrument/adapter/matrix/score
interfaces are mandatory released inputs; the release itself is externally pinned
and cannot recursively include its own digest. Additional upstream files remain
bound by the actual external entry records and are reopened, not inferred.

The completed bridge gate supplies its original intended12 matrix, build and
private-read references to the shared context_and_rows metadata loader. That
reopens the twelve historical rows and hashes their actual files under this
stage's Budget; it neither renders nor decodes them. The final38 matrix must
select that same noise admission and the externally pinned original69 instrument
result. This is the actual m194g-quality-instruments-v1 record consumed by the
production controller. Its59 adapter companion is separately obtained from the
genuine bridge read's adapter_controls FileRef. The earlier composite-gate
proposal is not implemented or required. All38 actual plans,
receipts, two launches/logs and TIFFs are independently admitted. All38 plan
completion times precede the first render start. Its six work fields include
complete plan refs, null failed launch, actual metadata/log bytes bounded by
64MiB, and the recorded240-second/16MiB per-child operational limits. Exactly38 initial TIFF decodes
precede reduction; the scene kernel then reopens34 flat and36 textured TIFFs.
The successful total is108 decodes, no optical cells and no random draws.

The target is the original complete K0 array, cross-bound to its own successful
16 controls and the externally pinned separate10-cell verifier. The verifier's
ten native coordinates, actual target values, signed differences, complete
private controls and unchanged source/input/release chain are checked. Its
original max0.004e/RMS0.0008e bars remain unchanged. Recomputing those saved
scalar differences is receipt consistency, not a fresh independent optical
measurement. Full scalar finite/nonnegative and NPY layout/extent checks use
the already commissioned bounded quality reader. Its float commission must be
the actual noise admission's float commission and its fixture the released
fixed fixture. No verifier-produced scalar copy replaces the target.

Success result has schema m194g-quality-score-v1 and status
COMPLETE_FIXED_QUALITY_DIAGNOSTICS. Exact keys are schema,status,ref_root,
artifact_ref_root,matrix,target,target_verification,instrument_commission,
bridge_commission,noise_admission,fixture,scalar,execution_release,invocation,
sources_before,sources_after,inputs_before,inputs_after,runtime,work,
geometry,region_masks,entries,scene_results,review_triggers,decode_reads,error,
finalization_errors,scope. ref_root is repository for its eight upstream
FileRefs and scalar ArrayRef; artifact_ref_root is result-parent for region_masks,
entries and scene_results. Other entries are actual finite JSON records. Failures use
UNCOMMISSIONED_QUALITY_STAGE and preserve earlier entries/scene results, original
error and secondary finalization errors; no incomplete result grants admission.

Region masks are seven original-name ArrayRefs, NPY bool[height,width], retained
from actual common crop/native coordinates before reduction. Scene_results has
two ordered FileRefs, flat then textured, each containing the unchanged complete
scene_readout tables. Entries are38 ordered FileRefs to separately persisted
complete actual read_entry returns, including their initial independent TIFF
evidence. Each entry uses entries/entry-NN.json, NN the actual ordinal00..37.
Only the admitted ordinal-to-pixel-hash map and common geometry stay resident
for repeated loads; the full plan/receipt objects are released after persistence.
Each child and final JSON remains under the original4MiB per-file cap, with all
writes under the unchanged32MiB cumulative score ceiling. Decode_reads retains all108 calls with
phase,ordinal,tiff and actual independently reconstructed pixel_sha256. No image
volume or decoded array is serialized in JSON.

Review_triggers retains all examined candidate-minus-baseline RMSE changes,
all paired variance changes/ratios and all noise-off wave amplitude changes,
including untriggered/opposing values. Literal flags are RMSE increase>1DN,
variance increase>2 percent (undefined at zero baseline, with underlying values
retained), and wave amplitude loss>1DN. These are descriptive flags, never a
quality pass, blur immunity, calibration claim or fitted selection rule.

The existing one120CPU/240wall/32MiB named-array/32MiB output/256 TIFF budget
starts before imports. Source snapshots, payload persistence, all observed
input hashes, current source identities and final post-write checks share that
same clock. Source metadata and timing are retained as observations, not a
performance comparison. Final result persistence uses the already held terminal
helper, which revokes success on final closure/resource failure.

# Complete pair adapter contract

`full-stack.rs` implements only the fixed complete70-source vitamin-C adapter.
The numerical engine/generated harness belongs to new_captures; independent
controls and source review belong to full_context_placement. This adapter author
performed no build, test, RAW read, candidate execution or quality judgment.

The root runner calls ignored test
`merge_cmd::shared_source_field::full_stack::vitamin_c_complete_pair`, supplying
`STREHL_SHARED_SOURCE_FIELD_FULL_CONFIG`. Its existing independent-screen check,
600-second wall limit and16GiB process limit remain the execution authority.
The adapter itself binds70 consecutive filenames, the held warp-map hash,
crop[28,19,3460,2306], A7CII ISO100 levels, active rectangle/stride, WB bits,
camera matrix, optical-profile key, seven reached bands and original tone.
It refuses local placement, the other fine-support candidate and directional
demosaicing.

Pass1 calls actual `BandWorker::fold` with canonical18,18,18,16 source groups
and the existing canonical absorb helper. One operator worker runs inside an
eight-thread pool. Source costs come from the author's exact retained finest
E/F bridge immediately after each fold. Per-source active-u16, all four actual
gathered planes, guide, variance, beta and E/F hashes are retained as evidence.
No source pixels or aligned images are retained across the source loop.

The completed baseline uses the actual four-plane writer. Its full RGB16 pixel
hash must equal the existing retained baseline before categorical aggregation
or candidate replay proceeds. Its collapsed post-hull G1/G2 form the one common
guide. Baseline worker scratch is dropped before allocating the second scalar
volume. Two full pixel-major cost arrays require4,468,105,600 bytes; that is
explicit scalar storage, not a claim of memory independent of source count.

The scalar engine's frozen methods normalize/aggregate/form memberships without
local labels or donor coordinates. D is released after memberships are formed.
Only the membership volume, activation and existing baseline accumulator remain
for replay. `activation.f32` records the row-major quad evidence activation
with dtype/shape/hash; it is not a depth-confidence or image-quality map.

Pass2 independently decodes each source, checks the active-u16 hash, and calls
the author's shared `gather_direct` helper using the same held map placement and
crop. Every plane hash must match pass1 before replay. The helper resolves
the actual source optical profile and uses the actual rounded GPU gather.
Replay receives one membership slice and one current gathered source. Hashes
after accumulation guard source/plane immutability. No noise model is refitted
and no new per-source variance probe is introduced.

The author's same `Replay` primitive produces four candidate CFA planes using
whole-AC accumulation, held terminal base and actual hull. Candidate and
baseline use the same actual writer/developer. The adapter writes `started`,
`baseline-ready`, `field-ready` and final `receipt` JSONs; the last includes
all70 second-pass checks, scalar hashes, participation summaries, coverage
error, complete output hashes and unchanged-original metadata/map checks.
File hashes and RGB16 pixel identity are recorded separately.

Progress reports name pass1/pass2 source counts, baseline finish/write,
categorical aggregation and final candidate write. Compact timing fields cover
pass1, baseline finishing, normalization/hash, aggregation/hash, memberships/
evidence/hash, replay and candidate finishing/write/hash. These include their
stated diagnostic overhead and are operational costs, not speed benchmarks.
Source engine direction-progress logging is owned by its author. No new image
observer or quality metric was added by this adapter.

# Next bounded implementation: stable, parallel complete-CFA wavelet

**ARGUED recommendation:** make one numerical/execution revision of the existing complete-CFA wavelet operator, then apply the same one-source resource gate. Parallelize its independent transform outputs and rescale its weighted accumulators. Keep the transform, eight independent probe pairs, injected noise, full GPU MHC/Catmull/CA gather, source order, boundary, weights, mean fallback and hull mathematically unchanged. Do not add another ownership prior or change the failed shared-source-field rule.

This is an implementation proposal, not a quality result. No code, build, RAW decode or candidate execution was performed for this note. Prior failures remain intact.

## Why this is the smallest justified next step

The shared field damages the compact core materially and fails its declared fan/near-detail requirements (`controls-1/output/screen.json`). Its categorical coherence does not establish correct ownership. Wider support, another source penalty or a confidence threshold would reopen the rejected information path.

The complete wavelet has a different information path: directional complex coefficients from all original CFA planes, with original-source noise propagated through the actual consumer. Its earlier fractional weak-red recovery exceeded baseline by about 2.58× while retaining relative RGB/boundary guards, but the absolute 90% focused-source and 5% error-benefit requirements still failed. That is only grounds for the already distinguished observational photograph, not promotion.

The full-size cost evidence is unusually actionable. `boundary-cfa-wavelet/cost-1/output/source-35.json` records 1.565031 s for the four-plane signal transform and 28.734747 s for 16 noisy-source gathers/transforms, within 31.708082 s source processing. The job used 40.953 CPU seconds over 33.141 wall seconds: about 1.24 effective CPU cores, despite an eight-thread execution pool. Source inspection confirms both one-axis transform loops are serial. The observed memory peak was 7,101,923,328 committed bytes. These observations establish available parallel work and memory headroom; they do not measure a speedup.

## Fixed implementation scope

1. **Parallelize output locations, not sources.** Horizontal analysis/synthesis can partition destination rows. Vertical analysis splits the destination into low/high halves and zips corresponding mutable output rows; each task computes the existing six taps for each column in their original order. Vertical synthesis partitions destination rows. Keep transform stages, recursion levels and source accumulation ordered. Process the four planes sequentially, retaining the existing workspace peak instead of allocating four concurrent transform workspaces. No SIMD reassociation, different filters, probe reduction, or new boundary is needed.
2. **Scale each coefficient's numerator and denominator by its running maximum weight.** Keep `m=max(previous_m,w)`, rescale old numerator/denominator by `previous_m/m` when m grows, and add `(w/m)*coefficient` and `w/m`. All-zero weights retain the original mean fallback. Continue obtaining each finite weight from the unchanged SoftPower rule, including its existing cap. This preserves the mathematical weighted result, though changed f32 association requires numerical controls. It avoids materializing `exp(80)*coefficient`, which can overflow for coefficients above roughly 6142 DN. A complete orthonormal coefficient can greatly exceed one photosite's value. The retained failure identifies numerator overflow only by strong source-level inference; it did not capture an offending coefficient.

The new running maximum is one padded f32 field: 64 MiB at 4096². Independent row execution needs no new image-sized buffer. Sixteen additional actual gathers and all original-source perturbations remain; no analytical covariance approximation or privately estimated noise is introduced. A GPU transform or general composed-covariance engine is a larger change than this measured serial bottleneck requires. Quantization, clamp behavior and reused original sites also make an unqualified linear diagonal-noise replacement incorrect.

## First falsifier and stop rule

Before any original is read, an independent control must show exact serial/parallel forward and inverse coefficient bits on the existing odd-boundary, small-axis and twelve-level fixtures. Separately plant a finite weight near `exp(80)` with a coefficient of 10⁷: the old product must overflow, while the scaled normalized result must agree with an independently evaluated f64 weighted mean. Include opposing signs, source-order reversal, unequal weights, seventy sources and all-zero fallback. Re-run the retained generated image/noise controls; preserve the old failed decision and inspect any numerical output movement rather than assuming it harmless.

Then run exactly one source-35 full-size cost phase, with actual CA, all eight probe pairs, reconstruction and writer. Retain the prior limits: measured peak below 12 GiB and `70*source_phase_seconds + finish_seconds + 120 <= 1500`. This needs a little over 1.6× source-time reduction before finish allowance; the measured low CPU utilization makes that plausible, not established. Do not choose thread/probe/filter settings by a sweep. Failure closes this bounded execution revision.

Only if those checks pass should root consider one complete observational vitamin-C pair with the exact historical baseline, held development and independent whole-image review against baseline/Helicon B. Faster execution does not imply better photographs; the operator still may preserve real late-source fans, and its prior absolute weak-colour failure remains disclosed. A negative full-image result ends this fixed route rather than licensing another local tuning program.

## Re-chosen failure points

- **Noise actually consumed, with matching units.** `manifest.rs:172-186` admits only zero covariance/variance or diagonal RGB variance 64 and proxy variance 24 in squared RGB16 code units. `mod.rs:289-300` derives the actual proxy `(R+2G+B)/4` from unnormalized merge-facing code values, allocates the actual constant f32 variance buffer, hashes it, and passes that same buffer to `add_frame_with_gain`. `mod.rs:245-260` copies the actual core white BandGain and passes its first three entries explicitly. Existing `pyramid.rs:1655-1659,1747-1803` uses the supplied override once and multiplies it by the corresponding variance; there is no extra normalization or double gain. Before/after hashes witness input/proxy/variance preservation. The independent verifier must check the actual buffer hashes and passed beta values, not only the manifest. The variance=1 product case is an early configuration refusal; positive-case actual-buffer checks provide the distinct consumed-input evidence. The simulation law and deterministic white operator probe remain neither physical RGB noise calibration nor empirical proof of finite-sample independence.

- **Literal contributor and address controls have power, but test different properties.** The three constant RGB contributors have literal mean (17000,23000,29000), unequal to every input. Actual `merge.frames()` after each call and three distinct consumed identities prevent a copied reference or omitted/duplicate fold from masquerading as the expected population. The asymmetric coordinate/channel field and constant color witness can reject a shift, channel permutation or second transfer even with the same dimensions/profile. Existing `pyramid.rs:2460-2470` finally clamps each output to the per-pixel input range, so identical inputs make that address oracle exact. This is an address/color integration control; it cannot validate unrestricted reconstruction quality. The source contract states that limit correctly.

- **Read bounds precede payload allocation.** `files.rs:115-159` checks plain-file type and extent before allocation, reads at most cap+1, compares same-API stability and verifies the same consumed bytes. The top-level manifest is at most 64 KiB and each TIFF at most 256 KiB. `manifest.rs:270-313` preflights unique LONG/count1 width 128 and height 96 before `CommonTiffFrame::parse` can allocate its width-times-height payload. The parser's other value arrays are range-checked against the bounded TIFF buffer before copying. Wrong-sized third input therefore refuses at its visit, without allocating the claimed wrong-sized payload. This does not independently establish process peak memory; the explicit-data bound and owned Job cap remain separate.

- **Refusal retains the intended prefix.** `mod.rs:82-108` creates the durable incomplete witness before manifest processing. Manifest path checks inspect paths/metadata, not future TIFF contents. Each input is content-authenticated at its visit, folded once, then recorded in memory and in a fresh immutable frame receipt (`mod.rs:263-332`). A structurally valid manifest with an existing wrong-sized or altered third TIFF reaches two prior folds and receipts. Errors from the third read/preflight occur before finish/output publication; the catch boundary emits a false completion result with the actual earlier prefix. Semantic manifest refusals legitimately occur before product binary/plan fields are filled; outer binary/command evidence must authenticate those refusals. Unexpected write failures may retain incomplete/partial artifacts and cannot be admitted from a positive-looking file alone.

- **Output contract reaches actual samples and profile bytes.** The profile is exactly 548 bytes with the held digest and is read before folding; each TIFF must contain the same ICC and exact structured provenance. `writer.rs:71-114` accepts the actual finished RGB planes, rejects nonfinite values, counts out-of-range values, clamps/rounds code values to u16, and embeds the actual profile bytes as UNDEFINED data. No Develop/camera matrix/WB/demosaic/transfer path is invoked. The constant TIFF description/software omit observer and path identities, allowing whole-file comparisons. The separate output parser must still check real tags and code values after a fresh build; writer source and a profile hash alone do not establish that a TIFF was correctly encoded. The old PROPHOTO_DISPROVED comparator verdict is unchanged.

- **Observation modes affect real work.** `mod.rs:137-196` returns before `averaged_fraction()` in off mode, allocates four inert GateRows without consulting the merge in placebo, and reads the actual shared accumulated-denominator fractions only in on mode. The final gate field reuses the last actual fold observation. `mod.rs:199-225` separately invokes the post-finish sample observer once: on copies/hashes real samples, placebo allocates/hashes the same number of zeros, off records invocation only. Mandatory encoding and pre/post output hashes are common to all modes, so off does not mean an absence of every hash operation. This matches the explicitly bounded diagnostic scope. Independent gate power must exclude the always-mean base and require zero and positive populations among actual Laplacian levels. Whole-TIFF/pixel/input equality remains the runtime nonperturbation proof.

- **Fresh publication and scope of identity are honest.** `files.rs:222-234` writes an owned fresh stage, links it create-only to the final destination, removes only the owned stage, and reads back exact bytes. An existing destination cannot be replaced by the hard-link publication. The own incomplete witness is explicitly authenticated rather than rejected as a collision. Unsupported links or later read/write failures refuse, leaving any orphan output unadmitted. Path checks reject reparse ancestry and case-folded canonical aliases; duplicate whole-input identities are separately rejected. As the contract qualifies, Windows checks are stable extent/mtime/attributes plus exact bytes, not an inode/volume-ID proof or a complete hostile-filesystem model.

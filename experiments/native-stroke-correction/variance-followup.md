# Dust gain and the existing variance path

**The missing factors are different for shot and read variance (DERIVED).** Let `d>=1` be the applied dust gain, `S` the original black-subtracted signal, `k` injected DN/e, and `r=RN_e*k` the injected read floor in DN. Away from clamps/rounding, correction gives `Y=d*S`. Original variance is `k*S+r²`; corrected variance is

`Var(Y)=d²*(k*S+r²)=d*k*Y+d²*r²`.

Evaluating the unchanged model at corrected signal returns `k*Y+r²`: shot variance is understated by `d`, read variance by `d²`. The total true/model ratio lies between those factors. Multiplying this already-corrected-signal model by `d²` would overstate the shot term by another `d`. Neither this derivation nor a synthetic control recalibrates `k` or `RN_e`.

**Exact current path.** `strehl-core/src/defect_map.rs::DefectMap::validated` (2462) takes the runtime validator's rescaled gains. `DefectMap::apply` (979) applies them to original u16 sensels, before warp: black-subtract/max0, multiply, restore black, round; original-white and restored-white cases skip. `strehl-cli/src/stack.rs::apply_defects` (719) passes the map and frame levels but returns only counts. Its `gain_dn_per_e` argument converts the HOT arm's electrons; it does not transfer dust variance.

`merge_cmd.rs::load_frame` (4975) calls that correction at5039, then the existing full-resolution/plane gather, optional direct rounded sink, extraction and `L=.5*(G1+G2)`. `align_cmd.rs::warp_frame_fullres_with_sink` (2152) black-subtracts and applies WB, reconstructs RGB from the complete CFA, gathers with the per-site CA-composed map, and undoes each destination site's WB. The corrected sensor gain/variance is not carried through that operation.

`BandWorker::fold` then calls `pyramid.rs::luma_variance` (562; call at merge_cmd.rs4921). That evaluates `noise.rs::green_luma_sigma` (309), using `PlaneNoise::variance` (114), at the corrected gathered luma. `BandMerge::add_frame_with_gain` (1742) Gaussian-reduces this spatial variance and uses `gate*beta[k]*variance` for band selection. There is already a per-pixel variance input: no new merge framework is needed for an opt-in local variance adjustment. Confidence's normal pass consumes corrected luma via the same loader but does not use this variance; do not describe a band-floor patch as recalibrating its debug confidence scores.

**The probe does not carry the gain either.** `gatefloor.rs::Probe::run` (274) clones frame metadata, then `fill_probe_noise` overwrites the samples with constant-variance synthetic noise. No defect plan is supplied. It follows the same gather/extraction but computes one spatially pooled beta per band, normalized by fixed `PROBE_SIGMA²/2`; its central pooling excludes an outer eighth. A small localized correction cannot be represented by modifying this scalar alone. Applying the real dust map to the existing positive-pedestal probe is also wrong: it creates a deterministic gain-shaped mean that enters Laplacian power. Global mean subtraction does not remove that profile. A future direct noise-transfer probe would need a matched noiseless subtraction or centered perturbations, not that shortcut.

**Smallest plausible next opt-in patch, with an explicit approximation boundary.** Keep the actual corrected u16/rounded gather and current transfer beta unchanged. In `load_frame`, retain only the sparse, actually applied sensor gains from the runtime-rescaled map (unity for skipped sites; a rounded sample that happened not to change still had the gain operation). Use the existing per-site reference-to-source/CA convention to transport that sparse field to the two consumed green sites. After ordinary `luma_variance`, add only the missing local contribution

`delta_v = .25*sum_G[(d_G-1)*k_G*G + (d_G²-1)*r_G²]`.

All-unity/off takes the old branch exactly; injected parameters remain unchanged. Accumulate directly into the existing destination variance buffer, with a small bounding patch around mapped support, rather than storing another full frame stack. Below-black/white/rounding boundaries require explicit refusal or separate treatment; the linear formula is not exact there.

This formula is exact for identity at the original source sites in the linear range, relative to the existing green-luma approximation. For full-resolution interpolation it is a **local-constant-gain approximation**, not a complete fix: Malvar mixes source colours, interpolation mixes source gains, and reconstructed G1/G2 can share source samples. Exact output variance is `sum_j w_j²*d_j²*Var(S_j)` for the COMPOSED luma weights, not a normally interpolated variance or just the gain at the nominal sample centre. Directional reconstruction additionally requires its chosen local linearization. If that approximation fails the bounded test below, do not promote it or expand this task into a general covariance engine.

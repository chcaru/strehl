1. METHOD
---------

ONE solve per subject, then N merges that differ ONLY in the interpolation
kernel used at gather. Verified live at the pinned SHA before this file was
written (pilot, wrapped-text-1, --limit 24):

  - `strehl align --out <sidecar>` writes `resampler <name>` as TEXT
    (warpmap.rs, `resampler_name`).
  - `STREHL_WARPMAP=<sidecar> strehl stack` loads it through
    `merge_cmd.rs::alignment_for`, which validates STACK IDENTITY and FRAME
    COUNT ONLY. It does NOT check the resampler, it never caches back, and it
    prints `alignment : ON (sidecar-override)`.
  - The CACHE path (`align_cmd.rs::load_or_solve`) DOES check the resampler and
    re-solves on a mismatch, and `solve_config_key` now hashes the resampler
    (the fact-1561 fix). So a hand-edited sidecar is honoured ONLY via
    STREHL_WARPMAP. Any arm run without that variable would silently revert to
    catmull-rom. This is the single most important methodological fact in the
    milestone and it is recorded here before any result.

  Pilot evidence that the edit is not a no-op (feasibility and timing only, no
  outcome metric computed): four arms on the same 24-frame solve gave four
  DISTINCT sha256s — catmull-rom 0833DDB6, lanczos3 BA3E3FB8, nearest 2E7C23D6,
  lanczos2 B543849A — at 8.5 / 36.5 / 6.3 / 26.6 s.

Every arm gets its OWN sidecar file and its OWN STREHL_CACHE_DIR (fact 1561).
Nothing is written under D:\.

4. METRICS, each with its stated failure direction (rule 18)
-------------------------------------------------------------

Measured on the BYTE-FROZEN measurement render: `strehl stack` with no --srgb,
16-bit binned linear camera-native RGB on the PLANE grid (3516x2344). That grid
is 1:1 with --index-map and --n-eff-map, so no resampling of mine enters any
analysis. Luma = the green plane, per the corpus convention.

M1  BAND GAIN (dex). log10 of radially-averaged power in 0.30-0.48 cyc/px,
    per tile, arm minus catmull-rom. Same band as M95/M113 so the numbers are
    commensurable.
    FOOLED UPWARD BY: aliasing (nearest will manufacture high-band power that is
    not signal), passband overshoot, and any sharpening. M113 measured this
    exact statistic reading +0.3510 dex for a pure x1.5 passband boost that
    carried NO new information. M1 ALONE CANNOT NAME A WINNER and I pre-commit
    to never quoting it alone.

M2  FLAT-ROI BAND GAIN (dex). M1 computed on the flat stratum. Rule 9.
    FOOLED BY: nothing that helps the arm — this is the control. An arm that
    gains here is amplifying noise or aliasing, not resolving detail.

M3  DISCRIMINATION = M1 - M2 (dex). The paired reading. Sharpness net of the
    noise/aliasing the same kernel adds.
    FOOLED BY: a kernel that smooths flat and detail equally reads 0 on M3 while
    genuinely differing. M3 is a discriminator, not a magnitude.

M4  FLAT-ROI SPATIAL SD, per arm, on the SAME pixels. The plain noise term, so
    that "sharper and noisier" can be said in those words. This is an
    arm-to-arm comparison of a spatial sd on one fixed region — like with like.
    It is NOT compared to any temporal sigma (rule 10).

M5  EXCESS-EXTREMA RATIO vs catmull-rom: count of strict 8-neighbour local
    extrema, restricted to the top-1% gradient stratum. Reference-free, M113's
    §5 instrument.
    FOOLED BY: it rises for ringing AND for staircase aliasing AND for genuine
    resolved detail. Admissible as a bound on artefact, not as a quality score.

M6  ELECTION AGREEMENT vs catmull-rom, from --index-map: fraction of quads
    electing the same frame, whole-frame and per 128 px tile. Feeds N4.

TILE / STRATUM CHOICE — fixed before any arm is looked at, and symmetric across
arms so no arm under test chooses its own scoring region (M113 discipline 752):
  - fixed geometric grid of 128 px tiles over the CENTRAL HALF of the plane
    grid. Central half because M113 measured whole-frame readings unstable
    (range 0.0806 dex across eight defensible tilings) since the border is
    featureless.
  - DETAIL stratum = top gradient decile of those tiles; FLAT stratum = bottom
    gradient decile. Gradient is computed on the ARITHMETIC MEAN OF ALL FIVE
    ARMS, so the stratification is symmetric by construction and privileges no
    arm. Deciles, not a DN threshold: an absolute DN tolerance is what produced
    the waxy-blob artefact (fact 1470).


5. BARS — registered now, reported as pass or FAIL either way
--------------------------------------------------------------

B1  REPLICATION. On bee-3-cpl, M1(lanczos3) over the detail stratum lands in
    [+0.060, +0.120] dex. M113's end-to-end range is +0.083 to +0.099. Outside
    this band my instrument disagrees with a published independent measurement
    and I report that rather than my own number.

B2  N4 — THE PRIMARY RESULT. On EACH of the two subjects M113 did not use
    (wrapped-text-1, flat-on-ruler-cpl):
       M1(lanczos3) in tiles with agreement >= 0.95  >  M1(lanczos3) in tiles
       with agreement < 0.95,   and corr(agreement, M1) > 0.
    PASS = the kernel earns the gain and the re-election dilutes it, replicating
    M113. FAIL ON EITHER SUBJECT = ORCH's N4 fires, the gain is a reshuffled
    election rather than better interpolation, and my report leads with a NO-GO.

B3  RULE-9 CONTROL, run FIRST and reported first. For every arm and subject:
    if M2 >= M1 the detail metric is measuring noise for that arm/subject and
    every M1 number for it is declared void rather than quoted.

B4  ORDERING PREDICTION, registered so it can be wrong. On M1 (band power alone)
    I predict   nearest > lanczos3 > lanczos2 > catmull-rom > bilinear,
    with nearest ABOVE lanczos3 because nearest aliases. If that ordering holds,
    it is positive evidence that M1 is aliasing-foolable exactly as stated in §4
    and it is NOT evidence that nearest is the best kernel. If nearest comes out
    BELOW catmull-rom, my stated failure direction for M1 is wrong and I must
    say so.

B5  NULL. One arm per subject re-rendered from a COLD cache with a
    byte-identical command line must reproduce the same sha256.

B6  PLANT — the null needs one (fact 1548). Two:
    P1 wiring plant: a sidecar whose resampler line is mutated must change the
       sha256. Already seen 4/4 in the pilot; repeated per subject.
    P2 metric plant: a known Gaussian blur of sigma = 0.5 px applied to the
       catmull-rom render must move M1 by more than 0.05 dex in the NEGATIVE
       direction, and a x1.5 passband boost must move it POSITIVE. Proves M1 can
       move on this wiring, in both directions, and re-demonstrates that M1
       rewards manufactured power.

B7  ADVERSARIAL POISONING. Render arm A cold; render arm B; re-render arm A.
    The two A renders must be byte-identical. A difference means an arm is
    receiving a kernel nobody asked for.

B8  COST. Wall clock per arm, reported as a BOUND not a value, since these runs
    are not thermally controlled and rule 16 applies. Reported because a default
    change carries it.

FAILURE IS A RESULT. If every arm lands within +/-0.02 dex on M3, I report "the
resampler choice does not measurably change the merged image on these subjects"
as the headline and do not narrow a bar to rescue an effect.

7. WHAT THIS CANNOT ANSWER
---------------------------

- It does not test the CA-corrected arm, so it cannot discharge ORCH's G2 (which
  requires the COMBINED CA + Lanczos-3 arm) and cannot speak to M110's finding
  that Lanczos-3 makes lateral chromatic aberration more conspicuous. That is
  the live objection and it is out of scope here.
- It measures the kernel AT GATHER with the warps held fixed. It does not
  measure solving WITH a different kernel (`align --resampler`), which changes
  the warps too.
- No ground truth exists for a merged image, so every metric here is
  reference-free or arm-relative. None of them is an accuracy measurement.
- M86's 0.98 -> 0.29 estimator-gain figure is about the DISPLACEMENT ESTIMATOR,
  not image sharpness. It is the reason to look. It is not quoted as a result.

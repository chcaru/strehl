## Consumer and bounded question

The single real call is the unchanged
`experiments/m193b-geometry-consumer/consumer.py::construct_overlap_paths` on the
nine independently admitted native derivatives. It returns the original M193
input-only overlap manifest and an in-process `TrustedInputBinding`, or the first
original exception. The runner does not implement another registration, mutate a
threshold, retry an inadequate pair, substitute a frame, or resume after refusal.

This tests whether the existing byte-reference registrar can construct its
denominator for these nine complementary-focus development inputs. It does not
authenticate a merged product's actual transform, complete a common-TIFF merge,
establish real placement truth, or qualify the M193c private output-grid adapter.
There is no new quality score. A complete result has status
`COMPLETE_NINE_INPUT_REGISTRATION_ONLY`; refusal remains a nonzero invocation.

The native TIFFs are CameraLinear, green-normalized as-shot-WB development
proxies. The frozen registrar's nominal ProPhoto luma coefficients and its
nearest-rank stretch are used as a fixed mechanical intensity projection, with
their original arithmetic. This is not a claim that CameraLinear samples have
become colorimetric ProPhoto. The independently admitted TIFF is already native
active-area RGB16: local integer pixel centres correspond to active-local source
centres. No orientation, resize, crop, demosaic or RAW read is added here.

Read-before-design sources are the architectural decisions in
`docs/research/SYNTHESIS.md`, M193c `charter.md` and
`registration-derivative-design.md`, M193/M193b reports and the frozen consumer
and reference implementation. In particular, end-to-end fit accuracy is not the
per-frame quantity consumed by a merge. The real native results are unknown truth.

in that ordering. Input invocation order and original index do not select it.
Reference and every source are recorded with all matching original aliases.

Its Q32 source-to-reference map is
`x_ref=(a*x_source-b*y_source+tx)/2^32`,

The original registration's held-out RMS limit of 1 reference-native pixel is

again to Q32, insert them into a product warp, or infer correctness from their
algebraic inverse relationship. Every coefficient has integer numerator and

## Cumulative resources and snapshot reservation

The original nonreset real-stage limits remain **1,200 CPU seconds, 1,800 wall
seconds, 4 GiB newly charged file bytes and 128 MiB metadata/log bytes**. Prior
work is the root-bound carry described above. The parent adds its actual process
CPU and the actual terminal worker Job's total user+kernel CPU. All helper and
image-library descendants are in that one Job. The original per-child limits
remain at most 240 wall seconds, 16 MiB live log and 8 GiB process-tree committed
memory, clamped to the actual remaining total; committed memory is not RSS.
Preparation does not reset child or total clocks. Child live callbacks must not
refuse merely because accounting is nonterminal. Missing terminal accounting
leaves `cpu_accounting_complete=false`, observed partial CPU or null, and no
complete-total claim; successful admission requires actual active-process count
zero. The actual helper outcome/log and limits are retained.

Exact source inspection establishes `construct_overlap_paths` calls
`decode_input_path` once per unique entry. The reference is decoded once, not
again after feature extraction. Each decode owns one file-backed temporary copy
of that complete TIFF, closed before returning its pixel array. Initial scan,
exact comparison and bundle hashing are read-only. Therefore the following
**prospective upper-bound reservation** covers every permitted temporary copy:

`sum(all nine admitted TIFF FileRef.bytes) + 5 * 1 MiB`.

The nine term intentionally counts distinct paths even if the consumer later
deduplicates their bytes. The five term covers one additional temporary snapshot
for each of the three same-focus and two complementary fixture TIFFs. Each
actual small encoded file must be at most 1 MiB before its constructor is called.
Only those three constructors are called: 3 inputs, 2 inputs, then 9 inputs.
The self-feature and arithmetic tests do not call the path decoder. No unused
reservation is refunded after first refusal.

This is not measured temporary I/O or peak storage. The parent charges the entire
reservation before the worker is launched and refuses if it does not fit within
4 GiB together with carried costs. Actual retained five fixture TIFFs, source
copies, controls, logs, requests and receipts are charged **separately** by
cumulative observed path-extent high-water marks. The copied consumer directory
alone excludes its `tmp*` files from that observed charge to avoid charging the
already reserved snapshots twice; `consumer.py` remains measured. No other
directory is excluded. Deleted or renamed observed outputs do not lower the
charge. Metadata is measured separately; reserved TIFF snapshots are not metadata.
The reservation may cause a refusal even when an early failed run would actually
write fewer bytes. It is never relabelled as physical bytes written.

The worker stores bounded metadata, at most 4 MiB per JSON, and no full-frame
volume. The unchanged consumer keeps one decoded image plus bounded current and
reference feature sets. The enclosing process committed-memory cap is the actual
memory enforcement, not an inferred Python array/RSS counter. The prior budget's
file inventory polling plus reservation accounts for completed/deleted snapshots;
it does not claim exact instantaneous write enforcement or zero polling overshoot.

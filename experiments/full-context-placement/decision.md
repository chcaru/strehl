# Full-stack local placement transfer

The September 14 eight-frame local experiment improved chip ladder crossings.
That does not establish a benefit with all 299 frames and seven pyramid bands.
The immediate decision is whether that photographic gain survives the actual
full RAW consumer. No new demosaicing, sharpening, inverse model, brightness
correction, or focus metric is introduced.

The fixed input is the committed local fit from frame 149 to frames 146–153,
read from `quality-september14/local-placement-consumer-inputs-1/manifest.json`.
Only its source-native displacement is used. Every configured original transform
is bound by its four f64 bit patterns. A 392×392 native support rectangle has a
32-pixel interior smoothstep transition. Its central 328×328 region carries the
full measured correction. The same gather correction runs on the synthetic noise
probe. Camera noise calibration remains injected unchanged.

Before RAW runs, independent generated controls must reject wrong direction,
factor-two coordinate error, incorrect CFA order, unsupported source stencils,
and invalid configurations. Zero/outside changes must be exact. A full-weight
patch must match the existing uniformly shifted-map consumer. See the independent
design for alternate choice points and the flat-signal/noise controls.

Full baseline/candidate runs use the same fresh executable, map, all 299 RAWs,
and pinned tone. Native views are at most 392 pixels per side: central photographic
detail, taper boundaries, and a far control. A sharper noise texture is not a win;
look for cleaner existing crossings without new structures, displaced borders,
or stronger chromatic speckle. A full-render null result closes this local-only
intervention as a quality improvement. No gradient-energy acceptance score.

The second scene is the newly supplied star sand, 259 RAWs. It is a transfer
test with porous grains and overlapping edges, not a replicate of chip texture.
No SOTA claim follows from either scene. Runtime from one replay is operational
evidence, not a comparative speed claim; alternating order is needed for one.

Prior-art search executed before this implementation:
`python -I -B experiments/ORCH-drift-check/prior_art.py local alignment refinement`.
Relevant record: M86 alignment, V-DRIFT, M97b visible alignment, M103 per-frame
placement, M23 local-linearity failure, M3 alignment, M78 blur equalisation,
M10 deep alignment, M6 residual support and M88b merge sharpness. The replacement
input is an independently held-out local translation fit, not a corrected chained
scale estimate or an endpoint alignment score.

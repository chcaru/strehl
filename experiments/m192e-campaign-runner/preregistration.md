## Persistence semantics and bounds

The adapter delegates each original observation once before its own bookkeeping. Every100 observations in on/placebo it serializes the current original sampler tail, aggregate drop/count/max fields, last observation timestamp, latest completed telemetry and a mode label. There are no extra product observations or new sampler phases. Restoration of both original Trace and telemetry function objects occurs in finally, including a sampler exception.

On/placebo must each have `checkpoint_count>0` in the actual production record. Off must have zero installed callback calls and zero checkpoints. The checker also requires the full callback census to agree with the actual sampler's sample and telemetry counts. A small run which never reaches100 observations fails the integration prerequisite rather than passing a storage-only demonstration.

Each invocation reserves two committed4MiB generations plus one4MiB staging extent. Initialization writes parseable INCOMPLETE defaults before monitoring. Each later save:

1. Encodes and bounds the whole next record before changing either committed generation.
2. Writes and flushes/fsyncs the staging bytes.
3. Atomically replaces the alternating committed slot within that directory.
4. Reads back the exact fixed extent/hash and retains only the latest two small generation witnesses.

The payload carries campaign ID, run ID, monotone sequence, previous committed full-file SHA and canonical payload SHA. The generation chain binds the two retained committed versions. The staging file is never a committed generation. Loss or corruption of one generation can leave the other recoverable; changed campaign/run identity in both, or an inconsistent pair of apparently valid linked generations, must refuse. Recovery reports errors and the selected valid generation rather than silently erasing corruption.

Every snapshot remains `INCOMPLETE`; recovery returns `RECOVERABLE_INCOMPLETE`, `may_resume=false`, `may_certify=false`. There is no promise that two generations contain the full run, that hashes prove physical truth, or that a recoverable snapshot supplies an absent terminal Job result. Recovery may display parent/worker terminal contents but cannot turn an unbound complete-looking file or escaped stdout into certification.

The original sampler limits remain4096 events,1000 observations,1000 telemetry rows and32 incidents with its original context tails. Counts of evicted rows remain explicit. The final monitor snapshot is bounded separately at8MiB. The callback's4MiB write/flush/hash can itself delay sampling. This is the integration subject: no source argument guarantees that it stays below100ms.

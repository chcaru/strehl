## Geometry, development and claim boundaries

V3 and native CA-off use the same held map SHA `4a76cd0c56c3a525e70f5bf72b965adb706131618c5bf49d0ae853fbf341c225`, reference149, delivered6896x4596 and original-reference offset(68,46). V3 gathers developed RGB with OpenCV cubic, while native uses original-CFA-fed MHC/Catmull/remosaic before its native consumer and final development. Same coordinates therefore do not imply the same sampled values or a pure selector comparison. V3 also rounds/clamps each gathered RGB tile to u16 before inference/fusion.

Helicon supplies its own alignment/reference/crop and outputs7020x4676. It is not on the native/V3 pixel gauge; corresponding landmarks and unresampled native witness crops are necessary. Common ICC SHA `238ad2596316306a72025bb245cf3c8cd72f1090c8d95af2f38dc090e84ece5b` supports common display interpretation, not identical upstream color/tone or geometry. Native tone is chosen after fusion; exported TIFF tone was rounded from a prior logged baseline and applied before fusion. Native CA-on is a separate arm and should not be silently substituted for the held CA-off master (`5dc571cc...e3fb655`).

No run controls the OS file cache or reproduces the same host load; hashing itself warms files. Helicon's application cache settings are logged, but an empty initial application cache is not a cold OS cache. Peak committed memory and differently scoped wall times are useful operational observations, not equal-resource benchmarks. A better complete comparator image could establish a practical quality gap for these exact workflows. It could not by itself identify alignment, interpolation, tone, demosaic, focus weighting or visibility as the cause, prove an optimized implementation's speed, demonstrate SOTA across the corpus, or satisfy the native-RAW reconstruction requirement. B4/B8/C are credible fixed alternatives, not an exhaustive vendor optimization.

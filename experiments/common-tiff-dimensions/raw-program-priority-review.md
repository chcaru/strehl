# RAW-native program priority review

Status: **ARGUED priority decision from existing VERIFIED/MEASURED records and a source-only consumer audit.** 2026-09-08. No new RAW, TIFF, model, metric, fixture, control, test or product execution. No new corpus pixel read. This document is the only artifact authored by this review; root owns implementation, experiment releases and commits.

**Recommendation: return to the existing native CFA consumer before implementing integer translation/crop in common-TIFF.** Keep the completed comparison interface and its reviewed integer design, but remove the assumption that its next extension must be the next product task. The extension is a useful conditional comparison capability; it is not a demonstrated prerequisite for the next RAW-native diagnostic. The owner's clarification reinforces the original product objective and supplies no new request to collect data.

The smallest useful next question is: **on one already recorded, fixed-focus sensor-control condition, does the frozen noise model supplied to the production CFA consumer predict independently measured temporal residuals at the actual green-luma/pyramid inputs to its gate?** First commission that finite native diagnostic, with unchanged production policy, using the existing ISO 160, 1/8-second paper and dark blocks named below. This is a transport/calibration diagnostic with a consumer, not a proposal to refit the profile until its own check passes, measure a new SOTA axis, or install a green-only covariance correction.

## Why the next RGB extension does not win this choice

The [integer-consumer audit](next-integer-consumer-audit.md) is careful about its own operator: u16 RGB inputs, integer source addresses, crop origins, full support, preserved declared white-noise law and a separate future problem for fractional covariance. Its scientific admission is correspondingly narrow. It does not establish that native CFA development depends on this RGB version. In particular, its starting premise that integer translation/crop is the “already-selected” next implementation chooses within the previous queue; it does not compare that queue against the now-restated RAW mission.

[M194](../../docs/research/M194-production-truth.md) already supplied the missing native experimental seam. `PyramidFrameSource` feeds decoded `Frame` values to the same production fold and confidence reread, with `RawPyramidSource` delegating to the RAW decoder. `run_pyramid_prepared` shares the production gather, merge, collapse and writer. Its saved synthetic/native checks establish that this seam exists and preserves the admitted output lineage. The current source agrees: `BandWorker::fold` calls shared `load_frame`, evaluates `luma_variance` with the injected `NoiseModel`, and passes the actual planes, luma, variance and per-frame beta to `BandMerge::add_frame_with_gain`. No common-RGB loader is in that dependency chain.

This is more than an abstract architectural preference. Native CFA retains active-area addressing, camera levels, individual photosite planes, white-balance context, sensor defect coordinates and the supplied shot/read-noise law before demosaic. The current gate-floor probe copies those frame properties because the native resampling transfer depends on them. An RGB integer extension cannot itself settle whether those quantities describe the samples the native gate consumes.

The current program's last amendment correctly pauses further TIFF implementation pending this choice. Retaining the already tested interface is useful; automatically expanding it postpones the particular sensor information the owner asked the program to exploit. Resume the extension when a named comparison experiment requires its known integer map, with an independently commissioned claim and source-to-consumer geometry. Its existence alone neither supplies real alignment nor repairs an invalid quality instrument.

The first useful result is a finite answer about the **current native input-to-band prediction**, with no candidate tuning. Retain native active-area/CFA addressing and camera levels; use same-site temporal variance on repeated input addresses, with independently written decoding/estimation checks. Trace the same sampled population through the existing production-source seam, actual defect treatment, extraction, green combination and pyramid transfer to the variance/beta the gate reads. Preserve the distinction between a warp-absent path, which falls back to the white band floor, and a placed identity transform, which exercises the measured-floor path. Identity addresses are a deliberate first isolation of sensor/consumer behaviour, not evidence that the real paper stayed motionless. If the finite input-only drift/illumination/support checks refuse, keep that refusal; do not fit a complex registration to rescue this calibration arm.

The dark block should also expose what the real black subtraction/clamp does. The existing beta probe intentionally sits well above black to avoid this nonlinearity. A mismatch near black must therefore be partitioned into input noise, spatial covariance and processing transfer; it cannot automatically be labelled wrong sensor gain. Preserve pre-clamp and consumed quantities distinctly. The paper block supplies a different signal regime, but five frames do not identify a complete photon-transfer curve. No profile is refit from these same residuals and then “validated” against them.

Before any execution, independently freeze the finite sampled sites, observation points, nuisance/refusal rules, minimum exercise counts and prediction bands. The diagnostic needs an explicit opposite-direction witness: wrong ISO/variance scaling or a wrong CFA address must change the comparison in its predicted direction, while an untouched observer/placebo must preserve output bytes. A synthetic witness checks software power; it is not the independent term in the real calibration comparison. Site selection must not use the same noise residual it will summarize. Keep all four photosite planes and within-plane neighbours visible so a green-only control cannot falsely isolate a sensor-wide effect. This should reuse the M194 consumer rather than introduce a second merge or an aligned-frame volume.

Stop at the first interpretable finite outcome. If the current prediction agrees over the admitted population, retain that limited calibration/transport fact and move to a separately chosen native quality mechanism; do not expand the matrix merely to manufacture a defect. If it disagrees, locate whether the error enters at decoding/levels, the injected model, neighbouring-sample transfer, clamp or the actual gate inputs before changing policy. If the temporal/geometry premise is refused, record the refusal and choose another already available development control under a fresh finite protocol. None of these outcomes license a local covariance patch, a new default, a photographic noise/detail verdict or SOTA.

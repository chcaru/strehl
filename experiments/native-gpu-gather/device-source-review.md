# Independent Device256 source review

SOURCE-REVIEWED only; no build, shader dispatch, numerical test, RAW decode or render by this reviewer. No remaining source blocker found for the fixed execution-5 allocation. Compilation, actual hardware admission and exact numerical commissioning remain unverified until root executes it.

The owned coordinate GLSL preserves the existing CPU grouping: original CFA parity selects R/G/B pulls; full-grid y includes the strip origin; native coordinates are formed from the current quad-centred f64 Similarity expression. Finite/support checks precede floor and f64-to-f32 conversion. INVALID and UNCONSUMED write all four descriptor words explicitly. All output lanes write one 16-byte descriptor; invocation and strip extents are guarded. Three dvec4 pulls occupy 96 bytes with the expected 32-byte stride, matching the Rust transform array and the separate existing 64-byte Params layout.

The final f32 fraction needs RTE but not subnormal preservation in this admitted domain: accepted native coordinates are at least 1.5, whose f64 spacing is at least 2^-52. Subtracting their integer floor is exact, and the upper support test ensures floor is already <= extent-3. Thus the difference is zero or at least 2^-52; conversion produces a finite normal f32 or zero. This argument does not apply to the preceding f64 transform intermediates, which still require the declared f64 rounding/subnormal/NaN/Inf contract. It is a domain proof, not a completed GPU test or an exhaustive proof for arbitrary alternative coordinate expressions.

Hardware admission requires discrete Vulkan, Vulkan 1.2, SHADER_F64, passthrough, f64 signed-zero/Inf/NaN and denorm preservation, and RTE32/RTE64. The logical device actually requests SHADER_F64. The initially missing denorm-independence refusal was fixed before hold: NONE is rejected because only width64 declares DenormPreserve; rounding modes at32/64 agree. These are distinct from merely advertising f64 arithmetic. The property and execution-mode requirements were checked against the [Vulkan float-control properties](https://docs.vulkan.org/refpages/latest/refpages/source/VkPhysicalDeviceFloatControlsProperties.html) and [Vulkan SPIR-V environment, VUIDs06289-06307](https://docs.vulkan.org/spec/latest/appendices/spirvenv.html).

The separate SPIR-V1.0 patch inserts the three enabling capabilities before other module sections, the required SPV_KHR_float_controls extension before imports/memory model, four execution modes after the existing LocalSize, and NoContraction decorations before types. IDs and original instructions are retained; instruction boundaries and exact removal identity are checked. Existing extensions/modes, fast-math, already-decorated arithmetic and fused operations are refused. The values/placement agree with the [Khronos float-control extension](https://github.khronos.org/SPIRV-Registry/extensions/KHR/SPV_KHR_float_controls.html). Only the embedded owned GLSL enters unsafe passthrough; no external shader is accepted.

Validation limitation is explicit and material: original GLSL/IR and original generated SPIR-V are parsed and IR-validated by Naga. The final additive float-control module receives structural/removal checks; Naga cannot validate those final execution modes here, and spirv-val is unavailable. This is not full final SPIR-V certification or an independent compiler validation. Fixed buffer bounds, integer-division checks and loop bounding are retained in the generated module.

Normal Device256 generates descriptors in a compute pass, then the existing gather reads that shared buffer in a separate pass of the same command encoder. It does not upload host Plan bytes. Workgroup counts, buffer limits and final-strip extents are checked; source/image packing, MHC/Catmull arithmetic, quantization, source preservation and output scatter stay on the existing paths. The control mutator deliberately reads actual device descriptors, mutates and uploads them; it cannot silently regenerate the reference CPU plan. That diagnostic path is separate from the ordinary resident-plan path. The shared context is still reused across actual RGB and green probes; GPU remains default-off, host schedules remain selectable, and unsupported Device256 requests fail explicitly.

The fixed standalone controls retain 37 real descriptor requests plus four API refusals: independently literal support/floor/tie words and exact source-f64 targets; live f32-coordinate/base-shift destroyers; distinct CA pulls and both green phases; 256+2 strips and full-grid concatenation; and NaN/Inf/overflow spanning two rows so blue actually participates. A copied CPU helper alone cannot satisfy the literal checks. Every visited row and failure is retained before the final assertion, and the actual coordinate compilation/hardware/mode report must be present. The unchanged18 image acceptance cases remain a separate requirement under Device256; neither successful descriptors nor a hardware refusal counts as image equivalence.

The fixed runners now bind successful descriptor/image reports through completion hashes and invocation build/test-executable identity, require the primary Device256 schedule, and require the original f32 image module hashes from run-4 (original41658a89..., submitteda7dce210...). The new GLSL feature cannot silently change that protected shader before native admission. Descriptor controls precede images; native112 off/on/placebo precedes109 CPU/GPU/GPU/CPU; any failure stops subsequent processes while retaining receipts. Native checks require complete corpus-specific TIFF/decoded hashes and exactly one RGB/green/device completion per expected call. Saved alignment, per-child limits and no-new-corpus-audit scope remain explicit; neither quality nor speed is established by this source review.

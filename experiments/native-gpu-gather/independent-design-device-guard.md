# Guarded device coordinates: fixed additional controls

This supplements, and does not replace or change, the original37 descriptor requests,4 API refusals and18 image cases. Run the new guard process first. No image equivalence, hardware availability or speed is presumed from the coefficient proof.

The admitted stored pull coefficients are zero, nonfinite, or finite with absolute value at least2^-900. Finite admitted coefficients are multiples of2^-952; centred native coordinates in quad units are half-integers, so finite arithmetic stays on the2^-953 lattice. This excludes f64 subnormal intermediates without requiring DenormPreserve. Signed-zero/Inf/NaN and RTE requirements remain. This is a sufficient domain restriction, not a necessary one: unsafe inputs fall back even when their final rounded coordinates would happen to agree.

Before GPU initialization, compare the exported threshold against literal f64 bits0x07b0000000000000. At each of all12 stored a.re,a.im,b.re,b.im slots, independently expect: signed threshold and next-up admitted; signed next-down refused; signed2^-901, minimum positive normal and signed minimum subnormal refused; signed zero, signed infinity and quiet NaN admitted. These192 checks operate on stored components directly, avoiding the lossy g=a.re-1 parameter conversion. No sweep or fitted threshold.

Concrete underflow witness: at native(37,27) in70x50, the centred quad coordinate is(1,1). Let L be minimum positive normal and a=(nextafter(L,+Inf),L). The current CPU complex product's real component is exactly minimum subnormal, literal bits1; flushing that intermediate to zero must change its bits. The guard must refuse the transform. This proves a dangerous intermediate exists; it does not claim final image pixels differ after later addition of the image centre. No unsafe coordinate shader is dispatched.

Four paired image checks reuse existing case1's complete padded, nonconstant colour source and photometry. Both arms use the same strict image shader: requested Device256 versus explicit Parallel256 CPU coordinates. The latter is the reference for routing, not a new CPU renderer. In order: R translation immediately below threshold; B translation minimum subnormal; all three a=(nextafter(L,+Inf),L),b=0; then an otherwise ordinary B imaginary scale exactly at threshold. First three must use actual Parallel256 with nonempty fallback reason, while the fourth must use actual Device256 with no fallback. The requested Device256 context must remain Device256 throughout, proving fallback is per call. Direct descriptor calls must refuse the first three and exactly match current CPU descriptors on the fourth.

Require complete packed u16 output and coverage-word equality, dimensions/counts/consumed denominator, live covered samples of every phase, nonconstant source, and unchanged original storage. Record first differing packed pair, CPU-coordinate operands, both code/coverage hashes, and actual schedules/reasons. As an additional route witness, unsafe calls and the explicit CPU planner must upload70*50*16 coordinate bytes; the safe device call uploads only the96-byte three-map buffer. No timing bar is attached to these byte counts.

Failure inputs include admitting a below-threshold coefficient in any slot, flushing the selected subnormal, dispatching unsafe coordinates, concealing CPU fallback behind a Device256 label, making fallback sticky, altering coverage or any consumed code, and modifying the protected f32 image shader. Zero/Inf/NaN predicate checks preserve access to the unchanged actual nonfinite descriptor control; they do not claim nonfinite images are useful captures.

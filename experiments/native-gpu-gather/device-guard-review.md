ARGUED prospectively: for the current coordinate expression, requiring every finite nonzero component of all three precomposed complex pulls to have magnitude >=2^-900 is sufficient to avoid f64 subnormal arithmetic. Every admitted binary64 coefficient is an integer multiple of2^-952. The bounded even native dimensions, native indices, quad pixel coordinates and centres produce exact half-integers; their differences remain exact half-integers. Multiplication by a coefficient therefore lies on the2^-953 lattice. Each finite add/subtract of these products, translations and centres remains on that lattice. RTE rounding preserves it: when spacing is finer the lattice value is representable; when spacing is coarser the rounded value is still a lattice multiple. Final multiplication by2 cannot reduce the quantum. Consequently a finite nonzero intermediate is at least2^-953, well above minimum normal2^-1022, even after cancellation. There is no division by a coefficient or other operation that could undo the bound.

Zero needs the retained signed-zero contract. NaN/Inf coefficients and overflow remain governed by SignedZeroInfNanPreserve64 and the existing invalid-descriptor path; their payload identity is unnecessary. The earlier accepted-coordinate proof still makes every final f32 fraction zero or >=2^-52, so only RTE32 is required there. These conclusions depend on the exact current grouping, half-integer grid and bounded dimensions; they do not establish a general denormal-free f64 shader.

The new domain must be enforced before device upload for every entry route, checking all12 actual composed coefficient values, including calls that consume only green. The strict device-descriptor helper must return Err outside the domain. An ordinary frame with an unsafe finite nonzero coefficient must use the retained Parallel256 CPU planner with the effective output schedule and an explicit fallback marker. It must preserve the original image input domain rather than reject a previously admissible frame. Native timing must require all expected Device256 completion markers, preventing fallback from silently qualifying as device speed.

Fixed falsifiers should assert both signs of the immediate binary64 neighbours below/at/above2^-900 using independently literal words, plus a tiny-coefficient strict-helper refusal and actual effective-Parallel256 fallback. Keep the existing descriptor and image equality gates unchanged. These controls will commission the guard/fallback; the lattice proof, rather than a finite set of tiny samples, establishes the subnormal bound.

This is an explicitly revised prospective device-domain contract after the first refusal. Removing DenormPreserve64 capability/mode/requirement is justified only together with that guard and truthful fallback; it does not retrospectively make the original hardware policy pass.

# Independent-view processing and output navigation

IMPLEMENTED and VERIFIED by root-scheduled tests; actual GPU exercise awaits product15. This is author implementation evidence, not independent photographic review.

The child consumer keeps its original local acquisition indices. Before every child, the parent emits opt-in `STREHL_UI_VIEW` JSON containing view index/count/name and source offset/count/parent total. The same existing progress enablement gates it; the event supplies no values back to the numerical consumer. Ordinary processing emits no context and retains its original identity mapping.

The desktop validates bounded ranges, order and labels, then resets the whole observation state and advances its diagnostic epoch. Phase, count, confidence, admission, source repair, geometry and image packets cannot carry into the next view. Thumbnails and process selections are projected onto the child-local axis; source browser requests, pair inspections and metadata actions map back to the original parent indices. A visible banner names View X/Y and gives its parent capture range; percentages, when shown for an engine phase, apply only to that view. There is no invented combined progress percentage.

A known fresh Independent views job waits for a valid context. If a bounded live-log read skips data, scoped observations clear and remain unavailable until another valid context arrives. Malformed, overlapping or backward contexts cannot relabel later child events. The saved full log remains the replay source. A final completed session uses its immutable per-view output summary instead of presenting the last child's counters as the bundle total.

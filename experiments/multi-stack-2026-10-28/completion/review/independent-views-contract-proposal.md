# Independent-view bundle: proposed engine and desktop contract

Proposal sent to root before product edits,2026-10-28. This is an additive product workflow for independent viewpoints, not a mosaic or3-D reconstruction. First intended real pair: b16 bug-1/100MSDCF underside and b18 bug-1/103MSDCF top. Both have299 originals; each retains its own native camera gauge.

## Dispatch and saved provenance

Add manifest mode independent_views (desktop label Independent views), preserving old default and serialization. One or more explicit passes (root confirmed single-view native/focus export remains useful); each may have ordered continuation directories. Primary is absent and rejected. Cross-pass precision grouping, reconstruction and automatic first-two-pass reproducibility are unavailable. Focus evidence is inherent to the bundle; no probability/metric-depth label. Root owns final CLI flag/mode policy, dispatcher and binding implementation.

Process each pass separately as a complete single-pass result in view-01/,view-02/, etc. Use the existing ordinary/native producer contract appropriate to saved focus output, without a cross-view alignment call. Each child has its own source census, calibration, fitting reference, full/cropped dimensions, alignment, photograph, linear master and focus fields. Source IDs must remain traceable to the root declared pass and original content hashes; child local ordinal0 is not root ordinal0 for every view. The dispatcher must not silently reuse an appearance Layers child's joint crop as an independent result. Reuse only correctly keyed original caches.

Root session.json/source-identities.json bind the requested pass order and all originals. Root completed.json keeps schema strehl.session-completion.v1, frames=sum originals, passes=N, outputs=N, primary_pass=null, pipeline=independent-views. New bundle.json schema strehl.independent-views.v1 references relative child directories and hashes of each completed/render receipt. Include mode and provenance, expected files, original identity ranges, view name and explicit gauge_scope=per-view. Root completion binds bundle.json and child completion receipts; each child retains its normal file/session binding. No fabricated root alignment.json.

For every view retain native RGB photograph/master, full_quad_geometry, output sensor origin/dimensions/step, original fitting reference identity and existing transform convention, camera metadata/calibration with provenance, and focus summary plus source-ordinal/width/prominence/modes/usable/refusal/coverage TIFF maps. Keep the current scalar geometry/index digests. Coordinate mappings and focus ordinals are meaningful only within that view. relative_pose, camera_intrinsics and metric_depth are null unless separately measured with documented provenance; a lens name or35mm focal length is not an invented camera matrix.

## Desktop behavior

Independent views is a separate session choice. Hide/clear primary on transition; atomically refuse incompatible immutable flags; explain Each view keeps its own coordinates. Render progress reports current view and total captures without claiming a joint network. Completed workspace uses existing output navigation, labeled View N of N and its saved name/count. Each active view loads only its own photo/overview/native tiles and focus geometry; reset zoom/pan to fit when gauge/dimensions change. Do not synchronize an ROI across views or show first-view diagnostics over another view.

Show per-view placement/capture counts and focus-shape/refusal language. Retain the whole bundle under history; saved selected view and edit/export recipe refer to its bound child. Export bundle copies bound native artifacts and compact manifest to a new destination without copying originals, creating a relative self-contained package. Selected-photo export remains available. Existing import-completed-session accepts the complete bundle through strict binding/path/count validation; malformed, partial or swapped child results refuse. No legacy exception is needed for a new schema.

## Required controls and real acceptance

- Two child fixtures deliberately have different dimensions, origins, camera metadata and focus ordinals. Import/navigation preserves each gauge, with no inferred transform; mismatched child identity/hash and missing focus artifacts refuse.
- Source census equality checks root pass ranges against child identities; duplicate original content across views refuses or explicitly loses independent-acquisition status, never silently duplicates evidence.
- Cancellation after child1 leaves recoverable partial output but no root completed receipt. Reopen must not present the unfinished bundle as Saved. Atomic publishing and path traversal/symlink checks reuse existing discipline.
- Ordinary defaults and existing session modes keep prior command/image behavior. Product mode/flags/save/import/navigation controls run through the real mailbox plus actual GPU screenshots, including active-view map/zoom changes and exported bundle reopening.
- Full real b16/b18 independent outputs, native witnesses and focus-map readback establish useful multiple-view preservation/export. They do not establish a common physical scale, calibrated depth, relative camera pose or an external3-D reconstruction.

This document is a proposed exact contract for root confirmation. Engine/schema changes belong to root; UI changes belong to independent_review after that confirmation. No new product source was edited to prepare it.

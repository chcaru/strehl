Batches contain at most the reserved lanes, capped4and limited by worker count/job count/available complete-probe memory. Only a bounded batch is submitted to Rayon, preventing nested work-stealing from activating an unbounded number of outer probes. Consumer execution occurs inside its configured pool.

Before cache access, the module checks configuration, checked numerical/report budgets, duplicate frame indices and every composed color placement for finite nonsingular values. Identical raw placement bits are serialized, a conservative superset of identical cache keys, including corrupt-entry repair. The batch collects Vec<Result<...>>, so current jobs join before an error is propagated; no incomplete batch returns to fusion. Prior completed atomic cache entries may remain reusable. This preserves the existing cache refusal/publication semantics.

Frame-keyed receipts are removed exactly once in unchanged source/group order. Source sampling, gain, noise/variance and fusion arithmetic remain in the existing serial consuming order.
